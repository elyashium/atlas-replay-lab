# Phase 0 evidence — 2026-09-27

**Local controlled demonstration: verified for this environment.** This is an
Orbital test page and synthetic Chromium profile matrix, not a customer target,
handset result, or hosted product claim.

## Source and environment

- Code revision at matrix start: `45d0370` (`Align camera fallback and budget gating`).
- Windows x64, Node `v20.18.0`, Chrome `154.0.8037.57`.
- The browser matrix uses CDP CPU/network/viewport/permission emulation and
  Chrome's synthetic media stream where camera permission is granted. It does
  not test physical cameras, Android/iOS hardware, Safari, real radios, GPU,
  thermals, or native XR.
- Jev was not configured. Runs used the local rule-based engine; no external
  calls were made.
- The focused low-CPU profile reported `cameraPermission: granted` but selected
  `interactive-2d`, so it did not capture camera imagery. The `camera-denied`
  profile now records `denied` and selects `interactive-2d`.

The forced-high baseline is the intentional failing half. On the constrained
profile, adaptive routing serves the low tier over the camera-free 2D scene,
reaches the declared end state, keeps the first frame nonblank (7.07% focal
coverage), and reduces transfer by 1,303,977 B versus baseline. This proves a
local routing comparison, not an app-code fix or a third-party business result.

The gate applies the requested severe-only timing rule: first-frame, TTI, and
p95 interaction misses block a critical run only when they exceed 2× their
declared budget. Lesser misses remain warnings. This full run ended SHIP with 0
blocking, 5 warning, and 1 informational finding. Warnings include 44.62%
dropped frames on `high-wifi` and non-severe first-frame/TTI overruns on
constrained profiles.

## Replay and visual evidence

- Baseline and adaptive replays both matched causal structure and all four
  checkpoint screenshots pixel-for-pixel (0.000% differing pixels). Quantized
  timing differed between real runs, as expected; neither clock was faked.
- Chrome synthetic camera imagery is not written for the low-CPU adaptive
  profile because capability safety routes it to the 2D scene. Other profiles
  that take `camera-xr` use Chrome's synthetic stream, never a physical camera.

  their emulated mobile viewport sizes. The generated HTML report itself was
